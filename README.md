# Finance Apps: three finance-operations apps on Express + BigQuery

Three small internal-tool style web apps that share one Node.js/Express backend and one
Google BigQuery dataset. **All data is synthetic**: it is generated by a seeded script in
this repo, and every name, vendor and company in it is fictional.

| App | What it does | Highlights |
| --- | --- | --- |
| **SPO**: Supplier Payment Overview | Editable invoice table plus open/closed payment dashboards | Aging buckets and KPIs computed in SQL (CTEs, `CASE`, `SAFE_CAST`), bcrypt login with roles, admin-only dashboards, inline edits written back with `UPDATE` |
| **SKYNET**: Automation tracker | Register and track automation projects, change requests, a wishlist and statistics | "Lowest free ID" query, multi-developer filters, charts with Recharts, SOP file uploads (multer) |
| **Asset PO Tracker** | Weekly snapshots of deal/PO approvals with filters per report date | Validated query parameters, dynamic `WHERE` builder with positional bind variables, management report |

## Architecture

```
 apps/spo      (React, :3001) ─┐
 apps/skynet   (React, :3002) ─┼──►  backend (Express, :5000)  ──►  BigQuery dataset
 apps/assetpo  (React, :3003) ─┘      src/routes/{spo,skynet,assetpo}      (SPO_*, SKYNET_*, Asset_PO_Tracker)
```

* **Backend**: Express. Every query goes through one wrapper (`backend/src/db/bigquery.js`)
  that binds parameters, unwraps BigQuery date/number types and applies a per-query cost cap
  (`maximumBytesBilled`).
* **Frontends**: three independent Create React App projects (React 18, React Router 6, axios,
  react-select, Recharts). Each one reads the API URL from `REACT_APP_API_URL`.
* **Database**: BigQuery. The schema lives in `backend/db/schema.js` (also exported as
  `backend/db/schema.sql`); `backend/db/seed/` contains the synthetic data generator.

## Getting started

### 1. Google Cloud (one-time)

1. Create a Google Cloud project that you own and enable the BigQuery API.
2. Enable billing and set a **budget alert**. The free tier (10 GB storage, 1 TB queries a month)
   is far more than this demo needs, but the apps run `UPDATE`/`DELETE` statements, which is a
   reason to prefer a billing-enabled project over the sandbox. Check the current BigQuery docs for sandbox limits.
3. Authenticate locally: `gcloud auth application-default login`

### 2. Configure and install

```bash
cp backend/.env.example backend/.env     # set BIGQUERY_PROJECT_ID (and optionally dataset/location)
npm run install:all
```

### 3. Create the tables and load the synthetic data

```bash
npm run db:setup     # creates the dataset and empty tables (drops existing ones)
npm run db:seed      # generates the data set and loads it with BigQuery load jobs
```

Dates are generated relative to *today*, so overdue and aging figures always look current.
Re-run `npm run db:seed` any time to refresh them. `npm run db:seed -- --dry` writes the generated
rows to `backend/db/seed/out/` without touching BigQuery.

### 4. Run it

```bash
npm run start:backend      # http://localhost:5000  (health check: /api/health)
npm run start:spo          # http://localhost:3001
npm run start:skynet       # http://localhost:3002
npm run start:assetpo      # http://localhost:3003
```

**Demo logins (SPO)**: `admin@example.com` (admin, sees the dashboards) or `user@example.com`,
password `DemoPass123!`. `newuser@example.com` is flagged as "password not yet changed" to show
the first-login flow.

## Design notes

* **Parameterised SQL only.** Values are always bound with `?` placeholders. Dynamic column names
  in the generic "save edits" endpoint are checked against `INFORMATION_SCHEMA` first.
* **BigQuery specifics handled in code**: no `ILIKE` (uses `LOWER() LIKE`), `SAFE_CAST` for typed columns
  receiving string input, one-element `UNNEST` instead of a `FROM`-less `WHERE`, load jobs instead of
  streaming inserts so that freshly seeded rows can be updated immediately.
* **Cost safety.** Each query is capped at 1 GB billed by default (`BIGQUERY_MAX_BYTES_BILLED`).
  If you ever host a public demo, also make it read-only or put it behind authentication.
* **No secrets in the repo.** Credentials come from Application Default Credentials; `.env` files
  and key files are git-ignored.

## Project structure

```
backend/
  src/server.js            Express app and route mounting
  src/db/bigquery.js       BigQuery client and executeQuery()
  src/routes/{spo,skynet,assetpo}/
  db/schema.js|.sql        table definitions (single source of truth: schema.js)
  db/setup.js              create dataset + tables
  db/seed/                 synthetic data generator and loader
apps/{spo,skynet,assetpo}/ React frontends
```

## Known limitations

* Demo-grade authentication: the SPO login keeps the role in `localStorage`, and the API itself does not
  verify sessions. A production version would issue signed tokens or sessions and check them server-side.
* No automated tests yet.
* Create React App is no longer actively maintained; migrating the three frontends to Vite is a natural next step.
